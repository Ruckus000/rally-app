# Rally — Week Spine

A social goal-tracking app. You **stake** a small number of tasks on a week, optionally **pair** with friends on them, and the circle **cheers** each other through. Points come from closing staked tasks; a leaderboard ranks the circle by follow-through, and a weekly **ledger** closes the loop.

This is a React Native (Expo) build of the design handoff in [`design-reference/HANDOFF.md`](design-reference/HANDOFF.md). The HTML prototype in that folder is the visual reference — it is read for structure, copy and interaction logic, and none of its templating is ported.

## Running it

```bash
npm install
```

```bash
npx expo run:ios
```

`npx expo run:android` for Android, `npx expo start` if a dev build is already installed. The native folders are generated by prebuild and are not checked in.

## Layout

| Path | What's in it |
|---|---|
| `src/theme/tokens.ts` | Every colour, type ramp, radius, shadow and the gradient-hairline definition. Nothing else hardcodes a design value. |
| `src/theme/motion.ts` | The four keyframes as RN easings, plus the `prefers-reduced-motion` hook every animated component checks. |
| `src/data/week.ts` | The single week-context object. Every "Week 33", date range and day count derives from it. |
| `src/data/fixtures.ts` | Mock people, tasks, moments, history, notifications. Explicitly not spec. |
| `src/state/store.tsx` | One reducer for the whole app; routes between overlays are explicit actions. |
| `src/state/selectors.ts` | Ranking, points, feed ordering, the ledger's helped/helped-by rollups. |
| `src/components/` | Primitives (`Bri`/`Sans`/`Caps`, `Tap`, `GradientHairline`, `GlowBloom`), avatars and rings, icons, the seven feed card types. |
| `src/screens/` | Week, Circle, Me. |
| `src/overlays/` | Plan, Ledger, Notifications, Join, and the detail sheet. |

## Decisions made on the handoff's open questions

The handoff lists seven gaps needing a product decision before building. What this build does:

1. **Week rollover** — `src/data/week.ts` exports one `WeekContext` (number, Monday-start range, current day, days left). Swap its anchor for a real clock and every week reference follows.
2. **Calendar math** — weeks start Monday, day 0 is Monday, dates render in the device timezone, and the week closes at the end of Sunday.
3. **Two creation paths** — both kept, but differentiated: a quick log carries `source: 'quicklog'` and reads "Quick log" in its category line, so it never looks like a stake worth 45 points.
4. **Task editing** — still not implemented. Tasks can be created and unstaked, as in the prototype. This is the one gap left open.
5. **True empty state** — the feed's empty card is implemented; a no-circle / no-history first run is still undesigned.
6. **Notification read state** — real per-item tracking (`notifRead`), so the badge counts what you haven't opened rather than clearing wholesale. "Mark all read" is available in the overlay header.
7. **Fixture data** — unchanged, and isolated in one file.

## Things the build adds over the prototype

- **44px hit targets** throughout, reached by expanding padding and hit slop rather than growing type.
- **Real dismissal** on every overlay — hardware back and Escape route through `src/overlays/Overlay.tsx`, and the sheet gained a close button (its drag handle is decorative).
- **Accessible names** on icon-only controls, on avatars (initials are decorative; the person's full name is the label), and on the year grid.
- **Reduced motion** disables the sheet and toast animations.

## Configuration

`<App config={…} />` takes the three props the reference modelled:

| Prop | Default | Effect |
|---|---|---|
| `showRank` | `true` | Off → hides podium rank badges, replaces list ranks with `·`, changes the Circle subtitle |
| `defaultAudience` | `'friends'` | Pre-selects the composer's SEEN BY |
| `quietComebacks` | `true` | Off → suppresses quiet comeback items from the feed |

## No backend

State lives in memory for the session. The reducer's shape maps onto what a backend would need: week-scoped task CRUD with audience and pairing, a cheer ledger keyed by actor, threaded notes per task and per person, a per-week rollup, a ranked circle, and a tiered notification service with batching.
